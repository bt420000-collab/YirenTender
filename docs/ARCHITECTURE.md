# YirenTender V0.1 初期架构

## 1. 总体思路

YirenTender 采用“项目中心 + 工作流核心 + 文档核心 + 审计核心”的架构。

第一阶段优先保证业务闭环和可维护性，不为追求架构复杂度而过早微服务化。

```text
                    ┌────────────────────┐
                    │      项目中心       │
                    └─────────┬──────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
        流程                 文件                待办
          │                   │                   │
          └───────────────────┼───────────────────┘
                              │
                           项目档案
                              │
          ┌────────┬──────────┼──────────┬────────┐
          │        │          │          │        │
         单位      人员       财务       审批      日志
                              │
                              ▼
                           项目归档
```

## 2. 核心能力层

### Workflow Core

负责：

- 项目生命周期
- 节点前置条件
- 状态迁移
- 异常分支
- TenderRound / 招标采购批次
- 待办生成
- 时间节点
- 节点完成检查

### Document Core

负责：

- 项目文件
- 文件分类
- 文件版本
- 正式发布版本锁定
- 文件与流程节点关联
- 文书模板
- 模板变量
- 自动生成文书

### Permission Core

采用：

**RBAC + 项目级角色**

公司/组织角色与项目角色分离。

一个用户可以在项目 A 是负责人，在项目 B 是审核人，在项目 C 只有只读权限。

### Audit Core

关键操作形成不可轻易抹除的审计事件。

原则上业务删除优先采用逻辑删除或状态失效，而不是直接丢弃历史。

### Archive Core

负责：

- 档案目录规则
- 必备项 / 可选项
- 缺件检查
- 归档前校验
- 电子卷宗生成
- 项目封卷

## 3. 推荐部署形态

V0.1 优先采用单体应用 + Worker：

```text
Web / Desktop Browser
        │
        ▼
Frontend
        │
        ▼
Application API
        │
 ┌──────┼────────────┐
 │      │            │
 ▼      ▼            ▼
DB   File Store    Worker
 │      │            │
 │      │        文档生成
 │      │        PDF处理
 │      │        AI解析
 │      │        消息通知
 ▼      ▼
PostgreSQL     Local/NAS/S3-compatible
```

首期不要求 Kubernetes，不要求微服务。

## 4. 代码仓库建议结构

```text
YirenTender/
├─ apps/
│  └─ web/                 # 前端应用
├─ services/
│  ├─ api/                 # 主业务 API
│  └─ worker/              # 异步任务
├─ packages/
│  ├─ core/                # 领域核心
│  ├─ workflow/            # 工作流/状态机
│  ├─ documents/           # 文档与模板
│  ├─ permissions/         # 权限
│  └─ audit/               # 审计
├─ rules/                  # 公共规则包
├─ templates/              # 通用文书模板
├─ docs/                   # 项目文档
├─ deploy/                 # 部署资料
└─ tests/
```

具体语言和框架在首个可运行原型前确定，不让技术选型反向绑架业务模型。

## 5. V0.1 第一优先级

1. 项目中心
2. 项目生命周期状态机
3. TenderRound 招标采购批次
4. 文件与版本
5. 待办 / 关键时间节点
6. 项目级权限
7. 审计日志
8. 归档完整性检查

AI、复杂财务、第三方平台接口、专家在线评审等能力放在主链跑通之后。
