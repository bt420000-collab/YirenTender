# YirenTender 许可与特殊部署政策

版本：V1.0  
生效日期：2026-09-26

> 本文件用于说明 YirenTender 的许可结构和项目政策。它不修改 GNU AGPL-3.0 的正文，也不构成对任何特定单位的自动授权或法律意见。

## 1. 默认许可：AGPL-3.0-only

YirenTender 核心软件默认按照 **GNU Affero General Public License Version 3 only（AGPL-3.0-only）** 发布。

在遵守 AGPL-3.0 的前提下，任何个人或组织均可：

- 使用
- 研究
- 复制
- 修改
- 私有部署
- 商业使用
- 提供技术服务
- 再分发

AGPL-3.0 的正式文本以仓库根目录 `LICENSE` 为准。

GNU 官方参考：

- AGPL-3.0: https://www.gnu.org/licenses/agpl.html
- GNU GPL FAQ: https://www.gnu.org/licenses/gpl-faq.html

## 2. 内部使用与网络交互

是否触发源代码提供义务，应以 AGPL-3.0 正文和适用法律为准。

需要特别注意：

1. 组织内部复制和内部使用，并不当然等同于向公众发布；
2. 但对于经过修改、并支持用户通过计算机网络进行远程交互的 AGPL 程序，AGPL 第 13 条要求向与该版本远程交互的用户提供获得对应源代码的机会；
3. 保密协议、内部制度或其他义务不会自动覆盖或取消 AGPL 已经存在的许可条件。

因此，在高度封闭、涉密、安全隔离或其他特殊环境中，如果使用单位无法同时满足其保密制度和 AGPL 要求，应在部署前评估是否需要另行取得特殊许可。

## 3. Confidential Deployment License

YirenTender 可以针对确有需要的特殊场景提供独立的：

**YirenTender Confidential Deployment License（YCDL）**

中文名称：

**YirenTender 保密部署特别许可**

适用场景可包括但不限于：

- 涉及国家秘密或依法需要严格保密的信息系统；
- 国防、军工及其他受特殊安全制度约束的封闭环境；
- 不允许向一般系统用户提供源代码的专用内网；
- 法律、行政法规、保密制度或合同义务明确要求源代码、部署细节或二次开发内容不得扩散的环境；
- 其他经项目权利人确认确有必要采用非 AGPL 授权方式的场景。

### 3.1 特别许可不是 AGPL 的“例外条款”

YCDL 是与 AGPL-3.0 **并列的独立授权路径**。

它不会修改 AGPL-3.0，也不会削弱任何已经按照 AGPL-3.0 获得软件副本的用户所享有的权利。

已经在 AGPL-3.0 下合法获得的版本，不能因为项目后来向其他单位授予特殊许可而被追溯改成闭源版本。

### 3.2 本政策本身不授予闭源权利

本文件仅声明项目可能提供特殊授权。

任何单位如需 YCDL，必须另行签署书面许可协议，并明确：

- 被许可主体
- 被许可的软件版本或代码范围
- 使用范围
- 部署环境
- 保密范围
- 是否允许修改
- 是否允许向承包商或关联单位交付
- 是否允许再许可
- 维护与升级
- 来源标识要求
- 第三方组件处理
- 终止条件
- 争议解决及适用法律

在正式协议签署之前，默认仍适用 AGPL-3.0-only。

### 3.3 来源记录原则

即使根据 YCDL 允许闭源或限制源码传播，原则上仍应在不违反保密和安全要求的前提下，于内部软件资产登记、源码版权头、交付文档或其他合理位置保留：

```text
Based on YirenTender / 一人招标
Original project: https://github.com/bt420000-collab/YirenTender
```

如公开显示来源本身可能造成安全、保密或合规风险，可以在特别许可协议中约定仅在内部权属记录中保留，而不要求向公众展示。

## 4. 为什么需要贡献者许可协议（CLA）

YirenTender 是社区项目。

外部贡献者提交代码后，贡献者通常仍然拥有其贡献部分的版权。

为了保证项目未来能够：

- 持续以 AGPL 发布公共版本；
- 对确有保密要求的场景发放独立许可；
- 统一处理侵权、来源和许可冲突；
- 避免出现某一段社区代码无法合法纳入特殊部署版本的情况；

项目要求重要外部贡献者接受仓库中的 **Contributor License Agreement（CLA）**。

CLA 不要求贡献者放弃版权。

贡献者保留其贡献的版权，同时向 YirenTender 项目授予明确的使用、再许可和多重许可权利。

详见：

- [CLA.md](../CLA.md)

## 5. 特别许可的权利边界

YirenTender 只能对项目权利人拥有版权，或已经取得充分再许可权利的代码授予特殊许可。

下列内容不因进入仓库而自动获得重新许可能力：

- 第三方开源依赖
- 第三方商业组件
- 政府公开文件
- 法律法规原文
- 国家标准、行业标准或地方标准
- 第三方模板
- 图片、字体、图标及其他受独立权利约束的材料

特殊部署版本必须逐项遵守这些第三方材料原有的许可证和权利条件。

## 6. 文档、模板与规则库

核心软件默认采用 AGPL-3.0-only。

文档、模板、公共规则库未来如采用与核心软件不同的许可，将在对应目录中以独立的 LICENSE / NOTICE 明确标识。

在独立许可尚未落地前，不应自行推定其可以任意改变许可条件。

## 7. 不得冒充官方版本

任何修改版、衍生版或特别部署版不得：

- 冒充 YirenTender 官方发行版；
- 暗示获得政府机关、监管部门或项目官方背书；
- 删除依法或许可要求必须保留的版权和来源信息；
- 对外使用容易使用户误认为其为官方原版的描述。

## 8. 法律审查

YirenTender 是开源工程，不是律师事务所。

在以下场景正式落地前，应由有资质的法律专业人员审查具体协议：

- 涉密系统
- 国防军工系统
- 政府采购或公共资源交易正式生产系统
- 商业闭源授权
- 大规模 SaaS 商业化
- 跨境部署
- 涉及第三方专有组件的再许可

项目文档提供的是许可结构和工程治理框架，不替代针对具体项目的法律意见。
